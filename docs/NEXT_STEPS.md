# Пять этапов развития кубической RPG

1. **Рефакторинг 3D-клиента (завершён):** модули не включают друг друга, только Application собирает их в кадр. Проверка: `ctest` + headless-кадр.
2. **Минимальный адаптер RPG Core:** без изменения алгоритмов алхимии связать игровую команду `gather` с реальной добычей одного ресурса. Проверка: один лот появляется в сохранённом `world_state.md`.
3. **Инвентарь и визуальные маркеры:** показать количество ресурсов из Core v3 в HUD. Проверка: перезапуск программы не теряет добытый ресурс.
4. **NPC и один заказ:** связать диалог с API производственного заказа. Проверка: кузнец отказывается без металла и принимает заказ с материалами.
5. **Процедурное отображение предмета:** отобразить геометрию простого клинка по данным Core v3, без Blender. Проверка: изменяется цвет/длина, но ID предмета сохраняется.

Сначала один проверяемый маршрут «рудное месторождение → инвентарь», затем каждая следующая функция отдельно. Не добавляем сетевую архитектуру, ECS, сложную геометрию и 3D-редактор заранее.
