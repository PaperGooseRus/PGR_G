# Архитектура v0.2

```text
main.cpp :: Application
  ├── World              → contracts.hpp
  ├── Movement           → contracts.hpp
  ├── Collision          → contracts.hpp
  ├── Interaction        → contracts.hpp
  ├── Camera             → contracts.hpp, raylib
  ├── Renderer           → contracts.hpp, raylib
  ├── TradeRules         → economy_contracts.hpp
  ├── RareDiscovery      → economy_contracts.hpp, OpenSSL RAND
  └── LedgerStore        → economy_contracts.hpp, SQLite, SHA-256
```

Включения одного `modules/*.hpp` в другой запрещены. `Application` выполняет единственное соединение компонентов и владеет состоянием. Независимость заголовков проверяет `tests/check_dependencies.py`.

## Один кадр

1. Принять ввод (главный поток, raylib).
2. Обновить `Player` через `Movement`, выполнить `Collision`.
3. Найти видимый ресурс/NPC через `Interaction`.
4. Если есть дискретная команда — `Application` проверяет условия, обращается к `TradeRules`/`RareDiscovery`/`LedgerStore`.
5. При изменении экономики обновить кеш `InventorySnapshot` и `EventRecord`.
6. По истечении одной секунды вызвать дешёвую проверку плановых событий природы.
7. Создать `HudState` из невладеющих указателей и отрисовать сцену.

В обычном кадре нет SQL-запросов, кроме действий игрока и редкого планового обновления. `World` статический, `SceneView` не копирует геометрию. Временные строки пользовательских уведомлений создаются только по событиям.

## Транзакции

`LedgerStore` владеет соединением SQLite. Любая материальная операция выполняется по схеме: `BEGIN IMMEDIATE` → проверки и изменение строк → дописывание хешированного события с контрольной суммой состояния → `COMMIT`. В случае ошибки RAII-транзакция вызывает `ROLLBACK`. SQLite обеспечивает сериализацию писателей; последующее внедрение потоков должно сохранять одного владельца состояния мира.

## Сохранения

- `save/game.sqlite`: новая экономика, события, контракты, ритуалы, правила синтеза.
- `core_v3/example/*.md`: примеры устаревшего ядра; не удалять.
- `elements.md`, `alchemy.md`, `world_state.md` старых миров **не импортируются** автоматически.

## Что не делаем сейчас

- Сеть/авторизация/серверные подписи и настоящий распределённый blockchain.
- Процедурная сетка мечей и анимационные скелеты.
- Разные потоки на каждого NPC и дерево.
- Перенос сотен существующих алхимических операций в новую систему за один шаг.
