# Сохранения, совместимость и ограничения

## Три файла

1. `elements.md` — прежний формат `RPG_ELEMENTS_V1`, односвязный список базовых элементов. **Не менять вручную порядок строк и колонку `next`.**
2. `alchemy.md` — необязательная **история старых экспериментов** `RPG_ALCHEMY_V1` из версии 2. Файл не меняется ядром v3, его можно читать командой `history`.
3. `world_state.md` — новый формат `RPG_STATE_V1`, один снимок живых персонажей, запасов ресурсов, лотов, предметов, навыков, заказов, открытий, знаний и событий.

Программа автоматически создаёт `world_state.md`, если его ещё нет. При этом существующий `elements.md` будет загружен, а не заменён, поэтому обновление v2 → v3 не стирает таблицу элементов или старую историю.

## Структура world_state.md

Разделы `Meta`, `Actors`, `Skills`, `Lots`, `Items`, `Nodes`, `Orders`, `Discoveries`, `Knowledge`, `Events` записаны в виде читаемых Markdown-таблиц. Каждая сущность, которой нужен идентификатор, получает уникальный ID. Встроенные детали не удаляются: они остаются доступными по ID для восстановления происхождения предмета, но имеют `owner=0` и больше не могут быть перенесены как отдельная вещь.

Парсер проверяет заголовок версии, наличие разделов, диапазоны свойств, отсутствующие ссылки, повторяющиеся идентификаторы, ошибки владения и нарушения резервирования. Неверные файлы отклоняются вместо бесшумного восстановления произвольных данных.

## Безопасность записи

Перед заменой существующего файла создаётся новая версия во временном файле `.tmp`, старый файл переименовывается в `.bak`, затем временный переименовывается в основной. При прерванной записи возможен запуск с резервной копией. Снимок новой экономики **один**, поэтому в нём нет необходимости синхронно сохранять несколько инвентарей.

Это не полноценная БД: нет журнала WAL, `fsync`, блокировок от второго процесса или синхронизации через сеть. Одновременный запуск нескольких копий игры в одной директории сохранений пока **не поддерживается**.

## Ограничения защиты

Файлы в Markdown редактируемы пользователем. Seed аномалий хранится в этом же файле. В локальной игре нельзя надёжно запретить чит-коды или декодирование скрытых закономерностей. В многопользовательском мире единственным источником истины должен стать сервер, а секретные условия не должны передаваться клиенту.

## Резервное копирование

Перед обновлениями ядра копируйте **все три** файла (`elements.md`, `alchemy.md`, `world_state.md`) вместе. Сохранения версии 3 не гарантируются совместимыми с будущими версиями без миграции. В этой поставке идентификаторы и имена полей считаются частью формата `RPG_STATE_V1`.
